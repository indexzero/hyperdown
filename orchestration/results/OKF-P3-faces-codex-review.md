## codex raw findings (verbatim summaries)

1. `materialize.js:222-231` — overwrites human-authored reserved `.md`
   (`index.md`/`log.md`) with no manifest entry; the `reserved` branch
   bypasses the N3 pending-ingest guard.
2. `materialize.js:251-263` + `:303-305` — removed files are left in the
   manifest (merge `{...current, ...next}`), so a later run can delete a
   human file that recreates those exact bytes at the vacated path.
3. `ingest.js:139-150` — containment escape: `ingestFile('../outside.md')`
   reads outside the bundle (no `containedPath` before `readFile`).
4. `ingest.js:240-263` — copy detection fails when the `_id`'s current
   view-path file is absent; emits `SetPath` instead of minting a copy.
5. `ingest.js:50` + `:187-191` — strips a `.conflict-<hex>` suffix from any
   human file, even a hand-authored `foo.conflict-deadbeef.md`.
6. `ingest.js:168-172` — a failed/skipped create (no `type`) still records
   the file hash in the manifest; a later materialize may overwrite/delete
   the human file.
7. `materialize.js:150-153` — silently drops a live concept when two resolve
   to the same `rel`, instead of surfacing it; omits a concept under I9/I11.

## Reconciliation (re-read the code against each finding)

**F6 — ACTIONABLE (N3 deletion-safety).** Confirmed and the most serious.
`_ensureConcept` returns `null` when `type` is missing/empty (`_create`
warns and bails), so `_ingestParsed` establishes no concept — yet
`ingestFile` unconditionally ran `_touchManifest(rel, hash)`. Trace: human
drops `draft.md` (no `type`) → ingest → manifest now has `draft.md → hash`
with no live concept behind it → next `materialize` §6 sees a
manifest-tracked path not planned, `onDisk === manifest[rel]` →
`atomicUnlink` → **the human file is deleted**. Not caught by the existing
N3 test (which never runs ingest on the file). Fixed.

**F2 — ACTIONABLE (N3 deletion-safety).** Confirmed. `saveManifest` merged
`{ ...current.files, ...next.files }`; retired entries (a renamed concept's
old path that this run unlinked, or a file already gone) were re-merged from
`current` and never dropped. Trace: `a.md` → rename to `b` → run 2 unlinks
`a.md` but the manifest still carries `a.md → H`; a human later recreates
`a.md` with the exact prior generated bytes → run 3 unlinks it as an
"orphaned prior output". Narrow (requires byte-identical recreation, e.g. a
git revert of the rename) but a real N3 hole reachable by ordinary rename
churn. Fixed.

**F1 — NOISE / by-design.** SPEC §9 defines `index.md`/`log.md` as derived
faces ("derived, never authored") that materialize regenerates every run,
and §9 ingest explicitly *ignores* edits to them. Overwriting a reserved
face is the mandated behavior, not an N3 violation; N3 protects concept
`.md` files the system did not materialize-and-track, which reserved faces
are not. The `reserved` bypass at `materialize.js:223` is intentional and
consistent with the ingest side. No change.

**F3 — NOISE.** The stated exploit does not work. `isIgnoredPath` splits on
`/` and rejects any path with a `..` (or dot) segment
(`'..'.startsWith('.')` is true), so `ingestFile('../outside.md')` returns
`[]` before any `readFile`. A leading-`/` argument is not an escape either —
`path.join(root, '/etc/x.md')` stays under root. Symlinked dirs/files are
skipped by `walkNotes` (`Dirent.isDirectory()`/`isFile()` are false for
symlinks). No reachable containment escape via the emitter or ingest. (A
belt-and-suspenders `containedPath` in `ingestFile` would mirror
materialize, but it fixes nothing real; not applied per "don't fix noise".)

**F4 — NOISE (stated trigger) + documented minor gap.** The stated trigger —
`_id A` at view path `docs/original`, only `docs/copy.md` on disk — is a
**rename**, not a copy (the original file is gone), and `SetPath(A,
docs/copy)` is the correct, minimal op. Copy detection correctly fires only
when a distinct file still holds the original path (`statOrNull(viewPath) !==
null`). There IS an adjacent real gap: when the view-path file is absent AND
two or more on-disk files share `_id A`, the contract's
"casefolded-lexicographically-first is original, the rest are copies"
tiebreak is not implemented (single-file `ingestFile` has no cross-file
view), so both files SetPath and the last wins with no `copydetect` flag.
This is exotic (a human hand-authoring two files with identical explicit
`_id` and deleting the original) and fixing it properly requires a
cross-file enumeration pass that the single-file, event-driven watcher
deliberately avoids. Documented as a trade-off; not fixed.

**F5 — NOISE / by-design.** SPEC §7 **reserves** the terminal pattern
`\.conflict-[0-9a-f]{8,}$`: apply rejects `CreateConcept`/`SetPath` carrying
it. SPEC §9 says an unknown-`_id` file with that suffix is a
`CreateConcept` at the **stripped** path (the epoch-cycle carry-across).
So a hand-authored `foo.conflict-deadbeef.md` with no `_id` becoming a
concept at `foo` is exactly the specified behavior; any resulting path
collision re-manifests under §7's ordinary rules (loser re-flags,
re-materializes at a conflict path) — no data loss. No change.

**F7 — TRADE-OFF (defensive, unreachable).** The `takenRel` guard fires only
for a state §7 declares impossible (two live concepts resolving to one
`rel`; pathcollision losers are deterministically suffixed by `_id`). The
drop is deterministic (`live` iterates `concepts.values()`, i.e. byte-key
scan order), so it does not break I9. It is an observability wart — a silent
skip rather than a surfaced report entry — for a corrupt-view "bug, not
state" case that §7 already says is CLI-reported only. Left as-is (surfacing
it would change the report shape for an unreachable branch); noted for a
future observability pass.

## Fixes applied (2) + regression tests

Each fix is an atomic commit on `12/okf-faces`; each regression test was
confirmed RED with the fix reverted and GREEN with it applied.

- **F6** `fix(okf-faces): ingest must not manifest-track a failed create (N3)`
  (`8402a6f`). `_ingestParsed` now returns `{ ops, established }`;
  `ingestFile` touches the manifest only when a concept was established. A
  type-less human file stays untracked and surfaces as pending-ingest.
  Test: `okf/test/faces-preservation.test.js` — "N3: a failed ingest
  (type-less file) never lets materialize delete the human file".

- **F2** `fix(okf-faces): prune retired paths from the emission manifest (N3)`
  (`03a4a19`). materialize tracks retired rels (unlinked or vanished) and
  deletes them from the merged manifest before save, so its own
  reconciliation is authoritative for them while still preserving the
  watcher's concurrent additions.
  Test: `okf/test/faces-preservation.test.js` — "N3: a renamed concept's old
  path is pruned from the manifest (no stale later delete)".

Suite after fixes: **212** passing (210 baseline + 2 regression tests),
0 failing.
